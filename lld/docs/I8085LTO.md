# I8085 LTO and Linker Scripts

Ordinary full and ThinLTO support section-pattern scripts such as
`*(.text .text.*)`. They do not preserve translation-unit identity. Use explicit
source section attributes when placement can be expressed without filenames.

`--lto-linker-scripts` enables a stricter full-LTO placement mode. Before modules
are merged, every defined function and datum receives a private section tag
containing its input-file owner and logical section name. LLD decodes these tags
before script matching. Static names, internalization, and prevailing weak/COMDAT
selection therefore do not require guessing from surviving native symbol names.

`KEEP` is applied to IR before linking and optimization, including local
definitions. `EXCLUDE_FILE` applies both to early retention and final placement.
As with a native link, KEEP cannot recover definitions already removed by the
frontend or compile-time optimization. Mark otherwise unreferenced C/C++
definitions `__attribute__((used))` when they must reach the linker.
Archive names use the existing `archive:member` script spelling. KEEP does not
force extraction of an otherwise unreferenced archive member; use normal archive
extraction rules or `--whole-archive` when appropriate.

Without an explicit source section, logical section names are `.text.<IR-name>`,
`.rodata.<IR-name>`, `.data.<IR-name>`, or `.bss.<IR-name>`. This mode intentionally
constrains cross-TU merging. Explicit function sections also prevent ordinary
I8085 outlining across placement boundaries. It is not a code-size optimization.

## Supported Boundary

This mode accepts **full LTO**, including Clang's full-LTO module summaries.
It rejects ThinLTO and unified LTO rather than reusing an index or cache that
lacks ownership. Full-LTO retention uses the updated IR roots, not stale summaries.
Module assembly, aliases, ifuncs, common/appending definitions, and TLS are also
rejected. LLVM bookkeeping globals (`llvm.*`) are not tagged.
Early KEEP flag matching supports SHF_ALLOC, SHF_WRITE, and SHF_EXECINSTR;
other flag filters are rejected because their native values are not known yet.
TU ownership applies to allocated code/data, not generated nonallocated DWARF or
other object-file metadata. Use section-only patterns for that metadata.

Nonempty generated allocated sections without an ownership tag cause a link
error, never fallback placement. This includes unowned constant pools, jump
tables, unwind tables, constructor tables, and newly synthesized helpers. For
freestanding code, disable unwind tables if they are unnecessary. If a program
needs one of the unsupported cases, use ordinary LTO and explicit sections, or
non-LTO compilation; do not suppress the ownership diagnostic.

I8085 tests cover two TUs with same-named static functions/data, KEEP without
`llvm.used`, prevailing COMDAT definitions, archive selectors, EXCLUDE_FILE,
linker garbage collection, and explicit rejection of unsupported inputs.
